Most introductions to Python quietly assume you already think in equations. If you come from the wet-lab bench, with plate readers, spreadsheets, and experimental protocols rather than a mathematics or statistics background, the first hurdle is not the syntax. It is the idea that a program is simply a list of instructions for a worker who follows them exactly.

Having made the transition from bench experimentalist to computational biology myself, these videos are my attempt to remove that hurdle, one small step at a time.

The idea behind the series

The goal is to help complete beginners understand how to work with Python without any quantitative background. One picture runs through all the videos: you are the customer, Python is the worker behind the counter. A function call is an order: you name the task and, in brackets, what to do it on. The worker does the job and hands back the result.

The series builds up in three steps:

  1. Basics: what a script is, the handful of symbols you must recognise, and how a function call is put together.
  2. Built-in functions: the 25 everyday tools that come with Python, shown one order at a time.
  3. Where Python runs: console, script and notebook, the IDE, folders and paths, installing tools, and reading your first plate file.

Video 1: Python basics (4 min)

The video opens with a situation most biochemists and cell biologists know well: a plate reader returns 96 numbers across dozens of plates, and someone has to count, add, and check them without losing track of a row. A script is a written list the worker follows exactly, and it gives the same answer every time you run it.

From there it covers, in order:

  • Python as a language, base Python as the toolkit of ready-made functions.
  • Arithmetic: +, -, *, /.
  • Assignment and comparison: = stores a value; ==, !=, <, >, <=, >= ask a question and answer True or False.
  • Function structure: the name, the round brackets, and the arguments inside them, with one, several, or no arguments.
  • if and indentation: a comparison decides whether the indented line runs, and the four spaces are grammar, not decoration. The video shows the IndentationError you get when they are missing.
  • Comments: a line starting with # is a note for people, not for the worker.

Video 2: Built-in functions (8 min)

After a short preface on the shop analogy, the video explains that built-in functions are the generic worker’s everyday skills, and that specialist libraries such as numpy and pandas are brought in with import when the job needs more. It then walks through three short movies, each a sequence of orders at the counter:

  • Counting and totals: print, input, len, sum, min, max, abs, round.
  • Converting and checking: int, float, str, bool, type, isinstance, list, dict.
  • Loops and collections: range, sorted, reversed, enumerate, zip, map, filter, any, all.

Video 3: Where Python runs (4 min)

The third video leaves the language and looks at the room it runs in:

  • Three places to type the same line: the console (one line in, one answer out), a script file ending in .py that you can run again tomorrow, and a notebook that mixes notes, code and results.
  • The IDE as the bench that holds editor, console, files and results side by side. Positron is one such bench; any will do.
  • The working folder and paths, and why FileNotFoundError is the most common beginner error: the file exists, but Python is standing in the wrong folder.
  • Installing specialists: what pip install does, and a virtual environment as one toolbox per project.
  • Closing the loop: pandas.read_csv reads the plate file into a table, and len from video 2 counts its 96 rows.

How the videos were made

Rather than recording a screen by hand, the whole series is generated deterministically from code:

  • Manim, a Python animation library, draws the operator, function-structure, if/indentation and comment scenes, and the folder, path, pip and read_csv scenes of video 3.
  • Plain HTML, CSS, and JavaScript, rendered frame by frame in a headless Chromium browser via Playwright, make the plate-reader opening, the shop-analogy preface, the console/script/notebook and IDE scenes, and the title and closing cards.
  • Kokoro, an offline text-to-speech model, provides the English narration.
  • ffmpeg mixes the narration into the picture and joins the scenes.
  • Claude, an AI coding assistant, wrote the scripts and the animation code, guided by reusable skill instructions for screencast production (part of the agentic workflows I explored in my previous post).

Every scene is generated from version-controlled text. That made this restructuring cheap: the new sections were rendered on their own, and the existing scenes were re-joined in a new order without re-rendering them.

Who this is for

If you know what a 96-well plate and a spreadsheet are, you can follow these videos. If something is unclear, the scenes are short enough to watch again, and the next step is simply to open a Python console and try the same lines yourself.
